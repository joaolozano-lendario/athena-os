## EXECUTION ENGINE: O CORAÇÃO DO MEGAZORD

### Ralph Loop Integration

Baseado no padrão GSD (Getting Stuff Done), adaptado para blueprints:

```yaml
Ralph_Loop:
  for each epic in blueprint:
    for each story in epic:
      for each task in story:

        # EXECUTION GATE
        1. read_task_definition()
        2. load_required_context()
        3. execute_task()

        # VERIFICATION GATE
        4. verify_completion_criteria()
        5. if not satisfied:
             - retry (max 2x)
             - or pivot_strategy()
             - or delegate_to_specialist()

        6. log_execution(metrics, lessons)
        7. update_blueprint_status()
```

### Dual-Gate Completion

Todo task passa por 2 gates:

| Gate | Pergunta | Falha → |
|------|----------|---------|
| **Execution** | Task foi executado? | Retry → Circuit Breaker |
| **Verification** | Critérios satisfeitos? | Ajustar → Re-executar |

### Circuit Breaker Pattern

```yaml
Circuit_Breaker:
  max_attempts: 2

  on_failure:
    attempt_1: retry com ajustes
    attempt_2:
      - analyse root cause
      - pivot strategy
      - ou delegate para specialist agent

  never: loop infinito
```

### Multi-Agent Orchestration

ATHENA spawna agents especializados quando:

| Condição | Ação |
|----------|------|
| Task requer foco profundo (>15min) | Spawn specialist |
| Context budget > 70% | Delegate com handoff |
| Domínio específico (copy, arch, etc) | Spawn domain expert |

| Usage | Status | Estratégia |
|-------|--------|------------|
| 0-50% | GREEN | Normal operation |
| 50-70% | YELLOW | Progressive loading |
| 70-80% | ORANGE | Summarize + compact |
| 80-90% | RED | Delegate para subagent |
| 90%+ | CRITICAL | Emergency stop |

### Memory Hierarchy

```yaml
Memory_Tiers:
  Core:
    - CLAUDE.md (identidade)
    - STATE.yaml (consciência)
    - Active Blueprint

  Active:
    - Arquivos sendo modificados
    - Context imediato

  Reference:
    - Docs de referência
    - Templates
    - Loaded on-demand (@filename)

  Cold:
    - Historical logs
    - Archived blueprints
    - Carregado explicitamente
```

### Strategy Selector

```yaml
Context_Strategy:
  inline:
    - quando: context < 50%
    - ação: carregar tudo necessário

  compact:
    - quando: context 70-80%
    - ação: summarize histórico + prune

  delegate:
    - quando: context > 80%
    - ação: spawn subagent com handoff completo
```

## NOVOS PROTOCOLOS v3.0

### P0: REFLECT (Pré-Pipeline)

**Trigger:** Antes de iniciar qualquer Blueprint

**Processo:**
```yaml
P0_REFLECT:
  inputs:
    - last_5_executions (observability)
    - current_request (do operador)
    - pattern_library (padrões conhecidos)

  questions:
    - "Este request é similar a algum anterior?"
    - "Que lições dos anteriores se aplicam?"
    - "Onde este pode travar baseado no histórico?"
    - "Que perguntas devo fazer preventivamente?"

  outputs:
    - adapted_parameters (granularity, depth)
    - preemptive_questions
    - anticipated_risks
    - relevant_patterns
```

### P5: EXECUTE (Novo em 3.0)

**Trigger:** Após Blueprint ser aprovado em G4

**Processo:**
```yaml
P5_EXECUTE:
  mode: autonomous_with_checkpoints

  execution_loop:
    for each epic:
      - load_epic_context
      - notify_operator (starting epic X)

      for each story:
        for each task:
          # DUAL-GATE PATTERN
          - execute_task()
          - verify_completion()
          - log_metrics()
          - update_state()

      - checkpoint_epic()
      - operator_review (optional)

  circuit_breaker:
    max_retries: 2
    on_fail: pivot_or_delegate

  completion:
    - verify_all_acceptance_criteria
    - generate_execution_report
    - trigger P6: LEARN
```

### P6: LEARN (Pós-Pipeline)

**Trigger:** Após conclusão de qualquer Blueprint

**Processo:**
```yaml
P6_LEARN:
  inputs:
    - blueprint_gerado
    - execution_metrics
    - operator_feedback (se disponível)

  questions:
    - "O que funcionou bem?"
    - "O que foi mais difícil que esperado?"
    - "Que padrão emergiu que vale capturar?"
    - "Como adaptar protocolos para próxima vez?"

  outputs:
    - lessons_learned
    - pattern_candidate (para Pattern Library)
    - protocol_adaptations (sugestões)
    - execution_report (para observability)
```
